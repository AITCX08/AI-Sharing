# 小白也能跟的 AI 开发流程

> 用 AI 写代码不是「想到哪写到哪」。给它一套**有章法的流程**，AI 不乱写、你不返工。下面这套来自开源的工程化工作流（superpowers 一类的 skill），小白照着走就行。

## 一条主线：构思 → 计划 → 执行 → 验证 → 收尾

| 阶段 | 干什么 | 解决什么 |
|---|---|---|
| **构思（brainstorming）** | 动手前先把「要做什么、为什么、边界」聊清楚 | 避免一上来就乱写 |
| **写计划（writing-plans）** | 把需求拆成 step-by-step 的小任务，落成一份计划文档 | 多步任务有路线，不迷路 |
| **执行（executing-plans）** | 按计划一步步做，每步有检查点 | 不跑偏、可回看 |
| **先写测试（TDD）** | 写实现前先写测试，让「做对了没」可验证 | 用证据代替「看起来能用」 |
| **系统调试（debugging）** | 卡住时按方法定位根因，再改 | 不瞎试、不越改越乱 |
| **完成前自验（verification）** | 声称「完成」前先跑验证拿证据 | 不空口说做好了 |
| **收尾（finishing）** | 决定怎么合并 / 收口 | 干净结束一段工作 |

## 配套：把每步存档

流程跑完，**把计划和结果存进 `plan/` 目录**（见同目录 `plan目录模板.md`）。流程 + 存档配合，才是小白做 AI 项目不失控的核心。

## 怎么获取

这类工作流是**开源 skill 集**，可在 GitHub 搜索 `superpowers skill` 找到并安装到你的 AI 工具里；安装后 AI 会在合适阶段自动调用，你也可以显式让它「按这个流程来」。

> 顺带两个我自己写的小 skill（见 `../我的skill/`）：
> - **req** — 需求澄清：把模糊想法说成清晰需求，AI 不乱做。
> - **teach-friendly** — 让 AI 用大白话教你，听得懂。
