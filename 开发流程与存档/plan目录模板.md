# plan/ — 开发计划存档体系（通用模板）

> 用 AI 写代码最大的坑：**AI 会丢上下文、改着改着乱套、项目一大就失控**。
> 解药很朴素——给项目建一个 `plan/` 目录，**每次开发 / 修复 / 重构完成，都留一份存档**。AI 和你随时翻得到「做过什么、为什么」，接着干不断链。

## 目录分类

| 目录 | 放什么 | 文件名示例 |
|------|--------|-----------|
| `开发规划/` | 技术方案、架构设计、需求（战略级蓝图） | `技术方案_v2.md` |
| `实施计划/` | 可执行的 step-by-step 计划（写计划的产出放这里） | `2026-06-01-阶段一-搭基座.md` |
| `功能开发/` | 单个功能 / 模块的开发存档 | `2026-06-05-登录功能.md` |
| `bug修复/` | 每次 bug 修复的存档 | `2026-06-08-列表不刷新-修复.md` |
| `重构与大模块/` | 大模块改造、架构级重构存档 | `2026-07-01-存储层切换.md` |

> 需要新类型（如 `评审记录/`、`决策记录/`）随时加目录。

## 命名约定

`YYYY-MM-DD-<简述>.md`，按日期天然排序。`开发规划/` 里的长期蓝图可不带日期（用版本号，如 `_v2`）。

## 每份存档写清五件事

1. **背景** — 为什么做这件事（需求 / bug 现象）
2. **改了什么** — 涉及的文件 / 模块 / 接口（具体路径）
3. **为什么这么改** — 关键决策与权衡
4. **怎么验证** — 验收 / 测试 / 冒烟方式 + 结果
5. **关联** — 对应的规划 / 计划 / 提交记录

## 存档时机（铁律）

- 每次**功能开发**完成 → `功能开发/`
- 每次 **bug 修复**完成 → `bug修复/`
- 每次**大模块 / 重构**操作 → `重构与大模块/`
- 写新**方案 / 架构** → `开发规划/`；拆 **step-by-step 计划** → `实施计划/`

> 小白记一句话：**别只顾让 AI 写代码，每做完一件事就留一份存档。** 这是把 vibe coding 从「玩具」做成「能长期推进的作品」的关键。
