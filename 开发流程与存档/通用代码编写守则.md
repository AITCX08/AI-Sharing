# 通用代码编写守则

> 适用于人和 AI 协作开发的任何项目、任何语言、任何框架。
> 目标不是把代码写得“复杂”，而是让它**能用、好改、可验证、出了问题能追查**。

## 1. 动手前：先把事情说清楚

- 先确认目标、影响范围、验收标准，以及明确“不改什么”。
- 不确定时先看相关代码、配置、数据库结构和现有流程；不要凭名字猜实现。
- 有多个合理方案时，说明推荐方案、代价和风险，再做会改变产品行为的决定。
- 小改动可以直接做；涉及支付、权限、数据迁移、删除或上线切换时，必须先说明影响并取得确认。

## 2. 修改原则：小、准、可回退

- 一次只解决一个明确问题，避免顺手重构无关模块。
- 优先复用现有组件、函数、配置和项目约定；不要为了“看起来高级”引入新框架。
- 不修改无关文件，不覆盖用户已有改动，不随意升级依赖。
- 需要破坏性操作（删数据、改表、重置配置、替换域名）时，先备份、确认目标，再执行。
- 配置、数据库结构和接口变更要考虑旧版本兼容；无法兼容时写清迁移与回滚方式。

## 3. 可读性：让六个月后的自己也能看懂

- 命名表达业务含义：`remaining_quota` 比 `n` 好，`is_admin` 比 `flag` 好。
- 一个函数只做一件事；复杂流程拆成能独立理解、测试的步骤。
- 注释解释“为什么这样做”和边界条件，不重复代码已经表达的“做了什么”。
- 不复制粘贴大段逻辑；重复两三次后，提取公共函数或组件。
- 避免魔法数字、隐式默认值和散落的字符串；集中成常量或配置。

## 4. 数据与安全：默认把风险挡在前面

- 密钥、密码、Token、数据库连接串只放环境变量或密钥管理服务，绝不写进代码、截图、日志或 Git。
- 所有外部输入都要校验：类型、长度、格式、权限和业务状态。
- 权限在后端校验，不能只靠前端隐藏按钮。
- 密码使用成熟的哈希算法保存；敏感字段和日志要脱敏。
- SQL 使用参数化查询；文件上传限制类型、大小和保存位置；接口设置合理的限流与超时。
- 报错给用户的信息要友好且不泄露内部路径、密钥、堆栈或数据库细节；完整诊断信息只写受控日志。

## 5. 异常与边界：失败时也要可控

- 对网络、第三方 API、支付、文件处理等不稳定步骤设置超时、错误处理和必要的重试。
- 修改余额、订单、额度、库存等数据时，保证幂等性（同一请求重复执行不会重复扣费或重复发货）。
- 关键写入使用事务；失败时要么完整成功，要么完整回滚。
- 清楚处理空值、重复提交、并发、权限不足、过期状态和第三方返回异常。
- 不用 `except: pass`、吞错误或伪造成功结果掩盖问题。

## 6. 测试与验证：用证据代替“应该没问题”

- 修 Bug 前先复现；修复后确认原问题确实消失。
- 新功能至少覆盖主流程、失败流程和一个边界条件。
- 优先自动化测试：核心业务写单元/接口测试，页面关键流程做浏览器测试。
- 配置或部署改动要检查：服务是否启动、健康检查、关键接口、日志、数据库连接和回滚路径。
- 只有运行过相关验证并看到结果，才能说“已完成”或“已修复”。

## 7. Git 与存档：每次改动都要可追溯

- 开始前查看工作区状态，避免把别人的改动一起提交。
- 一个提交只包含一个目的，提交信息写清“做了什么”。
- 大功能、重构和线上故障要留下简短存档：背景、改动、关键决策、验证方式和结果。
- 提交或上线前检查 diff，重点看密钥、配置、删除操作、权限、金额和数据库迁移。
- 对生产环境的操作记录时间、目标、执行人和结果，方便回溯。

## 8. AI 协作时的额外要求

- 让 AI 先复述理解，再写代码；涉及多步骤任务时先给简短计划。
- 明确告诉 AI：允许改哪些目录、不能碰哪些文件、完成后需要运行什么验证。
- 要求 AI 报告实际修改的文件、验证命令及结果，而不是只给结论。
- AI 不确定代码含义或会产生不可逆影响时，应停止并提问，不可自行猜测。
- 代码审查重点关注：安全、数据一致性、权限、错误处理、性能回退和缺失测试。

## 完成前检查清单

- [ ] 需求、范围和验收标准明确
- [ ] 没有泄露密钥、密码或用户隐私
- [ ] 没有误改无关文件或无关配置
- [ ] 主流程、失败流程和关键边界已验证
- [ ] 错误能被记录，用户不会看到敏感细节
- [ ] 数据变更有迁移/备份/回滚考虑
- [ ] 已检查 Git diff，提交内容单一且可理解
- [ ] 已记录验证方式与结果

## 给 AI 的通用指令模板

```text
请先阅读相关代码和配置，复述你理解的目标、影响范围与风险。
只修改完成此需求必需的文件，不要顺手重构或升级依赖。
涉及数据、权限、支付、密钥、删除或部署时，先说明影响并等待确认。
完成后运行相关测试或实际验证，并报告：修改文件、验证命令、结果、剩余风险。
```
